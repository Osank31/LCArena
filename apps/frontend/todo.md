One thing you haven't used yet that would help a lot here specifically: Anthropic's prompt caching. Your usage field already shows cache_read_input_tokens: 0 and cache_creation_input_tokens: 0 — caching isn't enabled. Since your system prompt is static and the prefix often only grows incrementally between calls, structuring the request so the stable portion (system prompt + editor_info) is cached would cut input-token cost substantially on every call after the first, independent of debouncing.
